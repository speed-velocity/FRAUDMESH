# Submission description

FraudMesh is an investigation-support console for reviewing suspicious transaction signals as a connected evidence network. It combines deterministic risk rules, alert triage, masked evidence review, entity graphs, bounded causal paths, case workspaces, audit controls, and a held-out synthetic event simulator. The design principle is: model fills data, code decides; every claim should cite evidence IDs, humans make every decision, and the dataset is synthetic.

FraudMesh uses NVIDIA Nemotron through Nebius Token Factory's OpenAI-compatible chat-completions endpoint. Server-side code builds bounded context from alerts, cases, graph links, and masked evidence before requesting a reasoning draft. Citation validation, output normalization, deterministic query execution, masking, rate limits, and human-review rules remain in application code. The same client powers live alert explanations, Nemo, case briefs, cluster stories, complaint intake, devil's advocate review, graph questions, council review, and scam-script classification.

The backend is FastAPI with SQLite persistence and the frontend is a React/Vite application. The repository includes local setup, smoke scripts, metrics for operational live calls, synthetic evaluation data, and deployment guidance. Limitations are explicit: the data is synthetic, hosted free-tier services may cold-start, Token Factory access and model eligibility depend on the account, and the evaluation is not a production fraud metric.
